# 求职展示材料

## 2～3分钟项目讲解稿

我做的是一个面向扫地机器人场景的 RAG 智能客服。用户可以咨询故障、保养和选购问题，也可以连续追问、查询指定城市天气，或者基于演示数据生成月度使用报告。

项目早期只有固定字符分片和向量 Top 3 检索，但没有客观指标，所以我先建立了60道人工标注评测题，其中55道有答案、5道无答案，并用来源文件和证据关键词定义 `KeywordHit@3`。原始方案只有60%的命中率。

分析失败案例后，我发现大量编号问答被固定长度切断，于是实现了结构化分片：优先按编号保持一条问答或故障记录完整，超长条目才二次切分。重新建立独立向量库后，命中率提升到89.09%，并通过MD5记录保证重复建库不产生重复数据。

随后我实现了中文BM25和RRF融合。向量检索与BM25各取10个候选，按照来源和正文去重，再用向量2、BM25 1的权重排序。混合方案也是89.09%，但延迟略高，所以我保留它作为实验能力，应用默认使用结构化向量检索。这个结果说明更复杂的算法不一定更好，需要用评测结果做取舍。

在可信性方面，RAG回答会标注 `[资料N]`，页面可以展开查看文件名、PDF页码和原文。知识库没有直接证据时系统明确拒答。工具异常会转换为用户可理解的提示，单轮工具调用限制为5次。项目还有16项离线自动化测试和60题检索回归门槛。

如果继续优化，我会拆分开发集与测试集来搜索融合权重，增加最终回答层面的事实一致性、引用正确率和拒答准确率评测，并把BM25索引和会话记录持久化。

## 高频面试问题

### 为什么结构化分片提升明显？

资料本身按编号组织，每个编号通常是一条完整问答或故障记录。固定字符切分会把问题、检测方法和修复建议拆开。结构化分片保持语义单元完整，因此查询向量更容易与包含完整证据的片段匹配。

### 为什么混合检索没有超过向量检索？

BM25改善了包含明确关键词的故障题，但对口语改写问题不稳定，部分关键词结果挤掉了原本正确的语义结果。等权RRF得到87.27%，向量与BM25按2:1加权后恢复到89.09%，仍未超过纯向量方案，因此没有将它设为默认。

### RRF如何去重？

项目使用标准化后的来源路径和正文内容组成文档键。两路检索命中同一片段时只保留一份，并把两路排名分数累加，同时记录它在向量检索和BM25中的原始名次。

### 89.09%代表什么？

55道可回答题中有49道在Top 3内找到至少一个符合人工标注来源和关键词规则的证据片段。它衡量检索召回效果，不代表最终生成答案有89.09%的准确率。

### 如何减少幻觉？

回答提示词要求事实必须来自检索资料并标注编号；没有直接证据时返回固定的资料不足提示。页面只展示答案实际引用的原文。报告生成还会检查数据查询状态，查询不到记录时禁止生成报告。

### 当前项目最大的不足是什么？

评测集规模较小，并且调参与评测使用同一批题，存在过拟合风险。下一步应划分开发集和测试集，并增加最终回答的事实一致性、引用正确率和拒答准确率评测。

## 演示顺序

1. 运行 `python -m pytest`，展示16项离线测试通过。
2. 启动Streamlit，询问“机器人找不到充电座怎么办？”。
3. 展开参考原文，说明 `[资料N]` 与原文对应关系。
4. 连续追问“多久清理一次？”，展示会话历史。
5. 询问“如何制作红烧肉？”，展示知识库外拒答。
6. 展示 `evaluation/results` 中60%、89.09%和RRF实验结果。
